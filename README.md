## Возможности

### Счётчики и показания
- Отдельные сущности для счётчиков, найденных в личном кабинете.
- Текущие показания, дата последней передачи и дата следующей поверки.
- Ввод показаний через Number-сущность и передача кнопкой.
- Передача показаний через сервис `tgc1.submit_reading`.
- Для горячего водоснабжения сущности имеют понятные имена с префиксом «ГВС:».

### Оплата через СБП
- Создание QR-кода для оплаты через СБП через сервис `tgc1.create_payment`.
- Проверка статуса платежа через `tgc1.check_payment`.
- Для создания платежа указывается обычный номер лицевого счёта; внутренний ID договора интеграция находит автоматически.
- После подтверждения оплаты интеграция обновляет данные задолженности.

### Квитанции
- Сенсоры даты и ID последней квитанции.
- Автоматическое обнаружение новых документов и persistent notification в Home Assistant.
- Просмотр PDF в браузере по временной подписанной ссылке. Ссылка действует 24 часа.
- Кнопка «Открыть последнюю квитанцию» создаёт уведомление со ссылкой на PDF.
- Кнопка «Скачать последнюю квитанцию» сохраняет PDF в `/media/tgc1/` на сервере Home Assistant.
- PDF не загружается автоматически при каждом обнаружении: файл скачивается только по запросу пользователя или через сервис.

### Несколько лицевых счетов и счётчиков
Интеграция создаёт сущности для доступных счётчиков и лицевых счетов. Если в личном кабинете несколько счётчиков, для каждого создаются отдельные сущности показаний и управления.

> **Статус тестирования:** интеграция проверена на счётчике ГВС. Работа с другими типами счётчиков и нестандартными конфигурациями личного кабинета может требовать дополнительного тестирования. Сообщения об ошибках приветствуются в [Issues](https://github.com/alshevskij/hass-tgc1/issues).

## Установка

### Через HACS (рекомендуется)

[![Открыть репозиторий в HACS](https://my.home-assistant.io/badges/hacs_repository.svg)](https://my.home-assistant.io/redirect/hacs_repository/?owner=alshevskij&repository=hass-tgc1&category=integration)

1. Установите [HACS](https://hacs.xyz/), если он ещё не установлен.
2. Откройте HACS → **Интеграции**.
3. Через меню в правом верхнем углу откройте **Пользовательские репозитории**.
4. Добавьте `https://github.com/alshevskij/hass-tgc1` с категорией **Integration**.
5. Найдите **ТГК-1: Личный кабинет** и установите интеграцию.
6. Перезапустите Home Assistant.

### Вручную

1. Скопируйте каталог `custom_components/tgc1` в `/config/custom_components/`.
2. Перезапустите Home Assistant.

## Настройка

1. Откройте **Настройки → Устройства и службы**.
2. Нажмите **Добавить интеграцию** и выберите **ТГК-1: Личный кабинет**.
3. Введите e-mail и пароль от личного кабинета ТГК-1.

Пароль хранится в конфигурации Home Assistant средствами самого Home Assistant.

> **Несколько лицевых счетов:** API ТГК-1 возвращает общий список квитанций. Поэтому сущности квитанций и кнопки работы с последней квитанцией привязываются к первому лицевому счёту в списке. Сенсоры задолженности создаются отдельно для каждого счёта.

## Сущности и сценарии использования

### Передача показаний

Для ГВС интеграция создаёт:
- **ГВС: ввод показаний** — поле для ввода нового значения.
- **ГВС: передать показания** — кнопка отправки.
- **ГВС: текущие показания** — сенсор текущего значения.
- **ГВС: дата последней передачи показаний** — дата последней отправки.
- **ГВС: следующая поверка счётчика** — дата следующей поверки.

Названия остальных сущностей зависят от названия услуги в личном кабинете.

### Сервис `tgc1.submit_reading`

Можно передать показания из автоматизации или скрипта:

```yaml
action: tgc1.submit_reading
data:
  entity_id: number.gvs_vvod_pokazanii
  value: 197.5
  max_increase: 30 # Необязательно; значение по умолчанию — 30
```

Укажите фактический `entity_id` вашей сущности ввода показаний. Сервис проверяет допустимое увеличение показаний и возвращает результат передачи.

### Сервисы QR-оплаты

Создать QR-код для оплаты через СБП:

```yaml
action: tgc1.create_payment
data:
  account_number: "номер лицевого счёта"
  amount: 1.00
```

В ответе сервис возвращает `payment_id`, `payment_url`, SVG-код `qr_svg`, сумму и номер лицевого счёта. Создание QR-кода само по себе не списывает деньги.

Проверить статус платежа:

```yaml
action: tgc1.check_payment
data:
  payment_id: 12345678
```

Сервис возвращает `paid: true` после подтверждения оплаты или `paid: false`, пока платёж не подтверждён. После успешной оплаты данные задолженности обновляются.

В атрибутах сенсора задолженности доступны внутренний `contract_id`, `account_number`, адрес и поля задолженности/платежей из личного кабинета. Для нескольких подключений можно дополнительно указать `config_entry_id`.

### Сервис `tgc1.download_document`

Скачивает PDF конкретной квитанции на сервер Home Assistant в `/media/tgc1/`:

```yaml
action: tgc1.download_document
data:
  document_id: 12345678
  # Необязательно: укажи ID записи интеграции,
  # если одинаковый ID документа найден в нескольких подключениях.
  # config_entry_id: "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
```

ID можно посмотреть в атрибутах сенсора **«ID последней квитанции»**. Сервис возвращает путь к сохранённому файлу. Если документ с таким ID найден сразу в нескольких подключениях, укажи `config_entry_id`, чтобы выбрать нужное. Существующие файлы не перезаписываются: ID документа добавляется к имени файла.

### Уведомления о новых квитанциях

При обнаружении новой квитанции интеграция создаёт persistent notification со ссылкой на PDF. Ссылка подписана и действует 24 часа. Она перестаёт работать после перезапуска Home Assistant или удаления соответствующего токена авторизации.

Также интеграция отправляет событие `tgc1_new_document`. В его данных доступны:
- `document_id` — ID документа;
- `name` — имя файла;
- `period` — расчётный период;
- `date` — дата документа;
- `url` — временная подписанная ссылка для просмотра PDF.

Пример использования ссылки в автоматизации: можно передать `trigger.event.data.url` в уведомление на телефон или в другой канал, который умеет открывать URL.

**Важно:** событие больше не содержит автоматически сформированный локальный `path`, поскольку PDF не скачивается при обнаружении. Если нужен локальный файл, вызовите `tgc1.download_document`: этот сервис по-прежнему возвращает `path`.

### Папка с сохранёнными квитанциями

Сохранённые файлы находятся в `/media/tgc1/`. Для быстрого доступа можно добавить кнопку на дашборд:

```yaml
type: button
name: Квитанции ТГК-1
icon: mdi:file-document-multiple
tap_action:
  action: navigate
  navigation_path: /media-browser/browser
```

## История изменений

### [2026.10.2](https://github.com/alshevskij/hass-tgc1/releases/tag/2026.10.2)

Повышена надёжность интеграции, обработки API-запросов и уведомлений о квитанциях.

- Усилена проверка ответов API: некорректные структуры и ID записей теперь обрабатываются как ошибки.
- Синхронизировано обновление токена авторизации при параллельных запросах.
- Повторная авторизация выполняется только для безопасных запросов чтения; POST-запросы передачи показаний автоматически не повторяются.
- Ограничен размер загружаемых PDF (25 МиБ), проверяется PDF-сигнатура.
- История обработанных квитанций сохраняется между перезапусками Home Assistant; старые документы не вызывают уведомления при первом запуске.
- Новые квитанции обрабатываются независимо друг от друга; неуспешная отправка уведомления или события не помечает документ обработанным.
- Имена PDF очищаются, к ним добавляется ID документа; существующие файлы не перезаписываются.
- Сущности новых счётчиков и лицевых счетов добавляются динамически.
- Сервис скачивания поддерживает выбор записи интеграции через `config_entry_id`, если ID документа совпадает в нескольких подключениях.
- Добавлены автоматические проверки кода, unit-тесты и проверка Home Assistant hassfest.

**Ограничение:** API ТГК-1 возвращает общий список квитанций без подтверждённой привязки к лицевому счёту. Поэтому сущности квитанций пока сохраняют привязку к первому лицевому счёту в списке.

### [2026.10.1](https://github.com/alshevskij/hass-tgc1/releases/tag/2026.10.1)

Первый релиз с календарной нумерацией версий.

- Добавлен просмотр PDF-квитанций по временным подписанным ссылкам без автоматического скачивания файлов при опросе.
- Добавлены автоматические persistent notifications о новых квитанциях.
- Кнопка открытия последней квитанции создаёт уведомление со ссылкой на PDF.
- Добавлена отдельная кнопка скачивания последней квитанции в `/media/tgc1/`.
- Сохранён сервис `tgc1.download_document` для ручного скачивания документа по ID.
- Добавлена HTTP View для выдачи PDF с проверкой доступа, документа и корректности PDF-ответа.
- Уточнены имена сущностей ГВС: ввод, передача, текущие показания, дата последней передачи и следующая поверка.
- Обновлена документация по событиям и сервисам.

#### Что это даёт на практике

- Можно получать уведомление о новой квитанции и открывать PDF прямо из Home Assistant.
- Можно отправлять ссылку на документ в собственные уведомления и автоматизации через событие `tgc1_new_document`.
- Можно не занимать место на диске автоматическими загрузками всех квитанций.
- При необходимости можно сохранить конкретный PDF вручную и использовать локальный файл в других сценариях.

## Решение проблем

Если интеграция работает некорректно, включите отладочное логирование:

```yaml
logger:
  default: info
  logs:
    custom_components.tgc1: debug
```

После перезапуска Home Assistant журналы доступны в **Настройки → Система → Журналы** или в файле `home-assistant.log`. При обнаружении ошибки создайте [Issue](https://github.com/alshevskij/hass-tgc1/issues) и приложите релевантные фрагменты журнала, предварительно удалив личные данные.

## Дисклеймер

**Это неофициальная интеграция.** Проект не связан с ПАО «ТГК-1» и использует внутренний API личного кабинета, который может измениться без предупреждения.

Используйте интеграцию на свой риск. Автор не гарантирует бесперебойную работу API и не несёт ответственности за сбои личного кабинета или последствия его изменений.
